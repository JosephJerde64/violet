# Zhongwen Resource Hub

Zhongwen Resource Hub is a curated technical index and navigation platform designed for developers, researchers, and content archivists who require structured access to Chinese-language media metadata, subtitle correlation datasets, and streaming endpoint references. The project does not host, cache, or redistribute any third-party content; instead, it provides a deterministic, machine-readable catalog of public uniform resource identifiers alongside a lightweight local toolchain for link validation, availability monitoring, and metadata extraction.

This project targets system administrators building regional content aggregation pipelines, academic researchers conducting longitudinal studies on Chinese-language digital media availability, and open-source developers who need reproducible reference datasets for testing network clients, parsers, or geographic routing logic. By offering a version-controlled index with structured annotations, Zhongwen Resource Hub transforms a flat list of domain names into a maintainable knowledge base that can be integrated into monitoring dashboards, automated health checks, and documentation generators.

## 功能概览

- **统一资源索引** - Maintains a master catalog of all referenced domain identifiers with classification tags, last-verified timestamps, and response status codes, updated through scheduled community-driven validation runs.

- **可用性探针套件** - Includes a modular Python-based probe engine that performs TLS handshake checks, HTTP HEAD and GET latency measurements, and response body fingerprinting against each indexed endpoint.

- **元数据抽取管线** - Extracts and normalizes HTML title elements, meta description attributes, and Open Graph protocol tags from reachable endpoints, storing results in structured JSON lines format for downstream processing.

- **变更检测差异器** - Compares current probe results against historical baseline records, generating delta reports that highlight new endpoints, removed endpoints, changed TLS certificates, and shifted geographic redirect chains.

- **静态站点生成器** - Consumes the validated index and metadata cache to produce a lightweight static HTML dashboard with sortable tables, filterable tag views, and per-endpoint historical trend sparklines.

- **RESTful 查询 API** - Exposes a read-only HTTP API under /api/v1 that supports endpoint lookup by domain pattern, tag intersection queries, and bulk status exports in CSV and NDJSON formats.

- **定时任务调度适配器** - Provides cron-compatible schedule templates and systemd timer units that automate daily probe runs, weekly metadata refreshes, and monthly full-index revalidation with email digest notifications.

## 应用场景

- **区域网络策略模拟** - Network engineers can use the probe latency and routing data to simulate user experience from different geographic origins, adjusting CDN selection and failover thresholds based on empirical measurements collected from diverse vantage points.

- **内容可用性学术研究** - Media studies researchers leverage the historical availability timeline and metadata snapshots to quantify the persistence of Chinese-language subtitle resources over multi-year periods, correlating domain lifespans with registration patterns and certificate renewal behaviors.

- **自动化文档系统集成** - Technical writers embed the live status badges and endpoint tables generated by the static site builder into internal wikis and operational runbooks, ensuring that team members always reference current and validated connection strings.

- **开源客户端测试套件** - Developers of HTTP clients, proxy servers, and DNS stub resolvers incorporate the domain index as a controlled test fixture, using the known set of endpoints to validate edge-case behaviors such as redirect handling, chunked transfer decoding, and gzip content negotiation.

- **监控告警基线配置** - Site reliability teams configure their Prometheus or Nagios instances to consume the probe result JSON, setting up alert rules that trigger when a predefined subset of critical endpoints fails to respond within acceptable latency windows across three consecutive checks.

## 快速开始

Clone the repository, install the Python dependencies, and run the initial index validation using the provided CLI tool. The following commands assume a Debian-based system with Python 3.10 or later and a standard POSIX shell environment.

```bash
git clone https://github.com/zhongwen-resource-hub/core-index.git
cd core-index
python3 -m venv venv
source venv/bin/activate
pip install --upgrade pip setuptools wheel
pip install -r requirements.txt
python -m zrh_cli validate --input resources/domains.txt --output reports/initial_validation.json
python -m zrh_cli probe --targets reports/initial_validation.json --concurrency 16 --timeout 10
python -m zrh_cli generate --data probe_results/ --output static_dashboard/
```

## 常见问题

**问：探针引擎是否会缓存或存储目标域名返回的实际媒体内容？**

不会。Zhongwen Resource Hub 仅记录 HTTP 状态码、响应头字段、内容长度摘要、TLS 握手耗时以及 HTML 标题和元描述文本。整个工具链不保存响应体（即 body 部分），也不解码或处理音视频流数据。所有提取的文本片段长度被限制在 1024 字符以内，且仅用于可用性分类和变更检测。

**问：如何更新域名索引？当用户提供的原始列表发生变化时，我应该如何操作？**

用户提供的原始列表以 `resources/domains.txt` 文件形式存储，每行一个域名。当获取到新的列表版本时，替换该文件内容，然后运行 `python -m zrh_cli validate --input resources/domains.txt --output reports/new_list_validation.json` 执行语法校验。校验通过后，使用 `python -m zrh_cli probe --targets reports/new_list_validation.json` 触发全量探针扫描。新结果将自动与历史数据合并，历史记录保留在 `data/history/` 目录下，不会丢失。

**问：静态仪表板生成失败，报错提示缺少模板文件或资产目录，如何解决？**

该错误通常发生在首次运行或执行 `git clean` 之后。请确保先执行探针命令生成了至少一份有效的 `probe_results.json` 文件。然后，确认 `static/` 目录及其子目录 `assets/` 具有写入权限。如果问题依然存在，尝试删除 `static/` 目录后重新运行 `python -m zrh_cli generate`，该命令会从 `src/zrh_cli/templates/` 内置模板中重新创建所有必要文件。
